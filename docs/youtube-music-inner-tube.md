# YouTube Music InnerTube catalog integration

Status: catalog/search and accessible public-playlist metadata are implemented. Track results retain the in-app YouTube embedded-player handoff. A typed Media3 source resolver now validates playback references from existing playable providers and explicitly rejects YouTube catalog IDs as audio sources. No YouTube track has played through Media3.

## Metrolist source review

The current Metrolist repository separates the app, its InnerTube models/parser module, and transport/extraction dependency:

- `innertube/.../YouTube.kt` wraps search and continuation calls and groups mapped results into songs, videos, albums, artists, and playlists.
- `innertube/.../pages/SearchPage.kt` maps `musicResponsiveListItemRenderer` entries to typed item models, extracting IDs from watch/browse endpoints, text runs, thumbnails, and page-type metadata.
- `innertube/.../pages/PlaylistPage.kt` maps playlist rows and continuation pages.
- `innertube/.../InnerTube.kt` delegates request construction and protocol operations to InnerTubeX and configures a Ktor HTTP client.
- `app/.../utils/InnerTubeXPlayer.kt` is the app's stream-resolution entry point. It uses InnerTubeX `InnerTubeExtractor`, player-config/cipher handling, and a WebView-backed PO-token provider before adapting resolved URLs and format metadata for Media3.
- Metrolist pins InnerTubeX as a dependency; its current repository declares GPL-3.0. InnerTubeX also declares GPL-3.0 and a Ktor stack. Sonic Sync does not copy those sources or add the library, so its licensing terms do not silently change.

References: [Metrolist source](https://github.com/MetrolistGroup/Metrolist), [YouTube.kt](https://github.com/MetrolistGroup/Metrolist/blob/main/innertube/src/main/kotlin/com/metrolist/innertube/YouTube.kt), [SearchPage.kt](https://github.com/MetrolistGroup/Metrolist/blob/main/innertube/src/main/kotlin/com/metrolist/innertube/pages/SearchPage.kt), [PlaylistPage.kt](https://github.com/MetrolistGroup/Metrolist/blob/main/innertube/src/main/kotlin/com/metrolist/innertube/pages/PlaylistPage.kt), [InnerTube.kt](https://github.com/MetrolistGroup/Metrolist/blob/main/innertube/src/main/kotlin/com/metrolist/innertube/InnerTube.kt), [InnerTubeXPlayer.kt](https://github.com/MetrolistGroup/Metrolist/blob/main/app/src/main/kotlin/com/metrolist/music/utils/InnerTubeXPlayer.kt), [Metrolist license](https://github.com/MetrolistGroup/Metrolist/blob/main/LICENSE), [InnerTubeX license and extraction notes](https://github.com/MetrolistGroup/innertubex).

## Sonic Sync behavior

`YouTubeMusicProvider` uses the public, unauthenticated `WEB_REMIX` InnerTube search and browse operations. It sends no cookies, account tokens, visitor/session credentials, or player requests. It maps result rows into track, album, artist, and playlist catalog entries, carries stable provider IDs and artwork/source attribution, and follows continuation tokens. Public playlist import is bounded to 20 pages/1,000 entries; entries are imported into Sonic Sync's own playlist metadata and matched against local files by the existing importer. Unmatched entries remain metadata and source links.

Discover exposes a YouTube Music filter, paged search, metadata rows, source opening, and public-playlist metadata import. Track results offer Watch, which opens YouTube's visible, branded embedded video player inside Sonic Sync. Playback remains in that player and does not enter the existing Media3 queue, notification session, or history. Albums, artists, and playlists remain metadata destinations.

`CatalogPlaybackResolver` is the Media3 queue boundary. Its existing-source implementation accepts only provider references already supplied by local MediaStore, Jamendo, Subsonic, Jellyfin, or Internet Archive; it validates local `content:`/`file:` URIs and remote HTTPS URIs and rejects credentials embedded in the URI. It returns a typed error for YouTube Music rather than treating a video ID or watch URL as an audio source. The current resolver does not refresh an expired source URL; retry reopens the current URI, while the user can browse/search again to obtain a new provider reference where that provider returns one.

The protocol is undocumented and can change without notice. Search and browse requests have bounded timeouts and response size, no authentication fallback, no account login, and typed offline/rate-limit/service errors. Public/search results may be region-limited, unavailable, restricted, or absent. Album/artist/playlist result links open the official YouTube Music destination; imported playlists do not sync back to YouTube.

## Playback boundary

The reviewed public YouTube playback route is the visible embedded video player. The official YouTube Data API exposes metadata/player embedding, not a public audio-only Media3 source. The unofficial InnerTube player route seen in Metrolist is different from catalog search: its `InnerTubeXPlayer` uses an extractor for player-response selection, formats, signature/cipher transformation, PO-token acquisition, and transport selection, then adapts expiring media URLs for Media3. Signature transformation is not Widevine DRM decryption; it transforms a signed/obfuscated URL parameter. That distinction does not make it a documented or authorized way to obtain a separately delivered audio stream. PO tokens are anti-abuse/integrity material. Sonic Sync does not decipher signatures, mint/acquire PO tokens, import cookies, or extract audio-only streams.

No independently verifiable, supported route was found that supplies a YouTube Music audio URL for Sonic Sync's Media3/background player without relying on that unofficial extraction path. A raw player response can contain direct, ciphered, adaptive, or token-gated formats depending on client/content; parsing a direct-looking `url` field alone cannot establish that it is authorized, stable, seekable, or playable without hidden request context. The remaining blocker is an officially supported audio-stream API/right or a different provider that licenses direct playback. This is not a missing Media3 adapter: there is no verified YTM Media3 source to adapt.

Watch loads the standard YouTube embedded video player with playback controls and visible YouTube branding. It validates video IDs before HTML construction, only loads an HTTPS YouTube embed, and pauses the player when the activity leaves the foreground. YouTube's terms identify the embedded player as an allowed viewing route and restrict automated access/circumvention; its API policies also prohibit separating audio and background playback for API clients. See [YouTube Terms](https://uk.youtube.com/t/terms), [YouTube API Services Developer Policies](https://developers.google.com/youtube/terms/developer-policies), and the [policy compliance guide](https://developers.google.com/youtube/terms/developer-policies-guide). The embedded player itself has not been exercised against a live service in this environment.

No YTM stream URL or quality value is fabricated. Codec, bitrate, sample rate, adaptive format selection, Media3 playback, background YTM playback, queue persistence, and stream refresh are unimplemented for this provider. The in-app embedded player requires network access and may not play age-restricted or otherwise restricted videos without YouTube's own supported access flow. YouTube playback cannot use Sonic Sync's Media3 equalizer, queue, or background controls.

## Re-check of public extractor alternatives (25 October 2026)

The current InnerTubeX repository documents an actual extraction stack: player/client selection, player configuration, cipher transforms, PO-token contracts, direct/HLS/SABR transport choice, format selection, and media probing. It currently describes a hosted QuackJS backend for player-cipher deobfuscation, and its README identifies GPL-3.0. The current Metrolist `InnerTubeXPlayer.kt` calls `extractor.extract(...)`, rejects SABR if its player path cannot consume it, adapts a selected stream to its own playback engine, and wires a WebView-backed PO-token provider. PO-token acquisition is distinct from media DRM decryption; cipher transformation likewise is not inherently DRM decryption. Neither fact makes the private player requests, anti-abuse token workflow, or direct URL a documented, authorized audio delivery API. Adding this resolver would create a dependency on a private, unstable extraction workflow and GPL obligations that have not been approved for Sonic Sync distribution.

NewPipe and NewPipeExtractor are another maintained GPL-3.0 route. NewPipe's project advertises YouTube Music support and background audio, and its extractor release notes show active changes to YouTube format extraction and SABR behavior. This confirms a technical extractor ecosystem exists; it does not provide authorization for Sonic Sync to use that path or settle the separate distribution/terms question. No NewPipe code or dependency is included. We do not characterize every cipher/signature operation as DRM: the blocker is that all candidate in-app audio routes inspected require undocumented YouTube delivery/extraction behavior, and no supported license/API for audio-only Media3 delivery is available to this project. Sonic Sync remains at catalog metadata plus visible YouTube embed.

Playable alternatives remain the already integrated Media3 sources: local MediaStore, Internet Archive (license metadata permitting), Jamendo (configured client ID), Navidrome/Subsonic, and Jellyfin. MusicBrainz remains metadata-only. These are never silently substituted for a YouTube result; provider identity stays visible.

## Verification

`YouTubeMusicProviderTest` uses deterministic response fixtures to cover anonymous request construction, entity mapping, continuation requests, playlist import pagination, invalid references, and offline failures. `CatalogPlaybackResolverTest` covers accepted existing-source URIs and the YouTube Media3-unavailable result. `YouTubeEmbedTest` checks that the in-app player HTML uses a validated video ID, visible controls, and the official YouTube embed. These tests do not establish live service playback. Live InnerTube search/browse and embedded-player operation require separate manual verification. No YouTube track has been verified playing in Sonic Sync during this milestone.
